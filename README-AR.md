# AADRI PRO — iOS 0.1.0

أُعدت من تصميم نسخة AADRI PRO لويندوز، بشعار المشروع الأصلي وألوانه. تستخدم SwiftUI وAVFoundation دون حزم خارجية وتتطلب iOS 16 أو أحدث.

بُني التطبيق فعليًا باستخدام Xcode 16.4 على macOS عبر GitHub Actions. حزمة `AADRI-PRO-iOS-Simulator.zip` تحتوي تطبيق `.app` للمحاكي بمعماريتي arm64 وx86_64، وليست IPA للتثبيت على هاتف حقيقي. راجع VERIFICATION.md لنتيجة الاختبارات وحدود التحقق.

## تجربة النسخة عبر Appetize

1. حمّل ملف `AADRI-PRO-iOS-Simulator.zip` المبني. عند تنزيل Artifact من GitHub، فك ضغط الحزمة الخارجية أولًا واستخرج ملف Simulator ZIP الموجود داخلها.
2. افتح Appetize ثم Upload وارفع **Simulator ZIP نفسه** واختر جهاز iPhone. لا ترفع حزمة المصدر.
3. داخل التطبيق اختر **تجربة المشغل بدون اشتراك** ثم **القنوات المباشرة** ثم **قناة تجريبية** ثم **ملء الشاشة**. العينة فيديو محلي مدته 8 ثوانٍ يمكن إعادة تشغيله؛ لا توجد قنوات تجارية أو حسابات جاهزة.
4. لإعادة البناء افتح مستودع `aadrijaouad1/Dreamtv` ثم **Actions → Build iOS Simulator → Run workflow**. حمّل Artifact باسم **AADRI-PRO-iOS-Simulator-and-Tests** بعد اكتمال التشغيل، وراجع نتيجة الاختبار أيضًا.

## إذا كان عندك Mac

1. افتح `AADRIPro.xcodeproj` باستخدام Xcode 16 أو أحدث.
2. اختر Scheme باسم AADRIPro، ثم جهاز iPhone Simulator مثبتًا.
3. اضغط Run لتجربة التطبيق. لا يحتاج المحاكي إلى حساب Apple Developer مدفوع أو شهادة توزيع.
4. لبناء حزمة Appetize من Terminal، من مجلد المشروع:

```bash
bash scripts/test-core.sh
bash scripts/test-network.sh
bash scripts/build-simulator.sh
bash scripts/test-simulator.sh
```

ستظهر حزمة المحاكي داخل `artifacts/AADRI-PRO-iOS-Simulator.zip`، ونتائج الاختبار والصور داخل ملف `.xcresult`.

## ما نُفذ في المصدر

- نفس الهوية الداكنة والزرقاء والشعار الأصلي، مع ترتيب مناسب للهاتف وبطاقات القنوات والأفلام والمسلسلات والرياضة والاشتراكات.
- واجهة عربية وإنجليزية، ووضع أفقي ورأسي على iPhone وiPad.
- استيراد روابط M3U/M3U8 وملفات UTF-8 حتى 150 MB، أو حسابات Xtream؛ حتى 6 اشتراكات.
- تصنيفات، بحث، مفضلة، سجل مشاهدة واستئناف للأفلام، وصفحات للحد من ضغط الواجهة على القوائم الكبيرة.
- عرض حلقات Xtream ومواسمها ودليل البرامج المختصر عند توفرهما من المزود.
- مشغل AVPlayer مع اختيار مسارات الصوت والترجمة المدمجة عندما يوفرها المحتوى، وإرسال الصوت/الفيديو عبر زر AirPlay النظامي.
- عند الضغط على التكبير: عرض يغطي كامل مساحة الشاشة ويتجاهل حدود المساحة الآمنة للفيديو، مع إخفاء شريط الحالة. الأزرار تبقى داخل المنطقة الآمنة.
- الوضع الافتراضي `fill` يمدّد الفيديو ليغطي الشاشة تمامًا؛ توجد خيارات الحفاظ على النسبة الأصلية أو الملء مع قص الأطراف.
- حفظ الهوية في Keychain، وتشفير بيانات الاشتراكات والمفضلة والروابط بـ AES-GCM، وحفظ لقطات القوائم قبل اعتمادها.
- الاتصال بنفس واجهات الموقع: تسجيل الجهاز والتفعيل والاسترجاع واستقبال قوائم الموقع وتأكيد استلامها بعد حفظها، وعرض تحديثاتها للتأكيد اليدوي.
- عرض MAC وKEY خاصين بنسخة iOS. لا يتم نسخ هوية ويندوز أو أندرويد إلى الآيفون. لن تظهر الاشتراكات المرتبطة بجهاز مختلف تلقائيًا.

## حدود هذه النسخة الأولى

- نجح البناء الأصلي على Xcode. لم تُختبر هذه النسخة على آيفون حقيقي أو داخل Appetize؛ نتائج المحاكي موثقة في VERIFICATION.md.
- مشغّل Apple يستهدف HLS وMP4 المتوافقين. حسابات Xtream تستخدم مسار `.m3u8` للقنوات. إن كان المزود يتيح TS فقط، فلن يكفي هذا المشغل دون تعديل المزود أو إضافة محرك تشغيل آخر.
- لا يوجد ضمان لتشغيل MKV أو AVI أو WebM أو ترميزات صوت/فيديو غير مدعومة، ولا يوجد محرك DRM مخصص.
- ترويسات EXTVLCOPT المخصصة تُكتشف ويظهر تنبيه واضح؛ لم يُستخدم API غير موثق لحقن الترويسات في AVPlayer.
- لم يُنقل بعد إدخال AADRI CODE ذو خوادم الاستكشاف، ولا PIN الأبوي، ولا تنزيل الأفلام للاستخدام دون إنترنت، ولا استيراد ترجمة SRT خارجية، ولا XMLTV مستقل. استخدم Xtream أو M3U في هذه النسخة.
- لا يوجد تحديث ذاتي مثل نسخة ويندوز؛ تحديث iOS الفعلي يحتاج مسار توزيع Apple ملائمًا.
- لم تُرسل حسابات اختبار أو طلبات تسجيل إلى موقع الإنتاج أثناء إعداد المشروع. التوافق مبني على قراءة الكود الحالي لواجهات الموقع، ويحتاج اختبارًا بحسابك بعد البناء.
- هوية Keychain تُحافظ عليها تحديثات التطبيق مع نفس Bundle ID والتوقيع. إعادة التثبيت ومسح الجهاز واستعادة النسخ الاحتياطية ليست ضمانًا لاسترجاعها.
- لا تسجّل دخول مزود حقيقي في رابط محاكي عام؛ العينة المحلية كافية لفحص الشكل والتكبير. عند تجربة حسابك استخدم جلسة خاصة موثوقة.

## الاختبار المطلوب بعد البناء

1. جرّب العينة المحلية: افتح الفيديو، كبّره، دوّر الهاتف، أخفِ الأزرار بلمسة، ثم ارجع. راقب عدم ظهور شريط التطبيق حول الفيديو.
2. من إعدادات الصورة بدّل بين Fill وFit وCrop؛ Fit قد يُظهر حواف سوداء وهذا مقصود للمحافظة على الأبعاد.
3. اخرج من وضع التجربة. من تفاصيل الحساب افتح الموقع باستخدام MAC وKEY الظاهرين وأضف اشتراكًا تابعًا لك.
4. تحقق من وصوله، ثم شغّل قناة HLS وفيلمًا وحلقة. جرّب البحث والمفضلة وتحديث القائمة.
5. أعد تشغيل التطبيق وتحقق من ثبات MAC وKEY والقوائم والمفضلة. حدّث التطبيق فوق النسخة نفسها لاختبار المحافظة على البيانات.
6. اختبر انتهاء التجربة وإيقاف الجهاز من لوحة التحكم بحساب اختبار، وتأكد من توقف المشغل. لا يوجد اختبار إنتاج تلقائي لهذه العمليات في الحزمة.

## التثبيت على آيفون حقيقي

حزمة Appetize لا تُثبت على هاتف حقيقي. افتح المشروع على Mac واختر جهازك ثم اضبط Signing & Capabilities إلى فريق Apple الخاص بك وبنفس معرّف التطبيق. التوزيع على أجهزة أخرى أو TestFlight يحتاج إعداد التوقيع والتوزيع المناسب. لا توجد شهادة أو مفاتيح Apple داخل الملفات.

## ملاحظات للمطور

- Bundle ID: `com.aadripro.ios`، الإصدار: `0.1.0`، أقل نظام: iOS 16.
- لا يحتاج CocoaPods أو npm أو XcodeGen. يمكن إعادة إنشاء المشروع عبر `python3 scripts/generate_project.py`.
- `NSAllowsArbitraryLoads` موجود لدعم خوادم IPTV التي يضيفها المستخدم عبر HTTP؛ اتصال التفعيل نفسه ثابت على HTTPS ويرفض التحويلات. يلزم تقييم هذا الإعداد ومتطلبات مراجعة Apple قبل التوزيع العام.
- `PrivacyInfo.xcprivacy` يصف استعمال توقيت التشغيل وحفظ معرّف الجهاز والتواصل التشغيلي مع الموقع. راجع إفصاحات الخصوصية الفعلية وسياسة الموقع قبل التوزيع العام.
- مشاركة معلومات الاشتراكات المحلية مع الموقع متوقفة افتراضيًا ويمكن تشغيلها من الإعدادات. تظل بيانات هوية الجهاز وحالة تشغيله ضرورية لواجهات التفعيل. المحاكي التجريبي الآلي يستخدم `--ui-testing` في Debug فقط ويتجنب الموقع كليًا.
